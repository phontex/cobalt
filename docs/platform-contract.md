# Cobalt Platform — контракт

Платформа — привилегированный исполнитель. Она не содержит APK, не скачивает файлы и не
собирает приложения. Всё, что она делает, она делает по явному запросу, в котором названы
пакет, версия и файл.

## Кто что знает

| Компонент | Знает | Не знает |
|---|---|---|
| Cobalt App | каталог с сервера, какие пакеты поддерживаются, где лежат payload-файлы и их SHA-256 | пути к APK на устройстве, права root |
| Cobalt Platform | где лежит установленный APK, его версию, как смонтировать и откатить | что переводить, откуда брать данные, что такое каталог |
| LSPosed-часть Cobalt | как подменять текст в рантайме, словарь | файловую систему за пределами своего процесса |

Направление запроса: **платформа спрашивает приложение не сама** — приложение передаёт роль
командой `configure`, а действия (`mount`, `umount`) инициирует приложение, потому что только
оно знает про каталог и payload. Платформа при этом остаётся офлайн-исполнителем.

## Файлы на устройстве

```
/data/adb/modules/cobalt-platform/   каталог модуля (bin/, action.sh, service.sh)
/data/adb/cobalt-platform/
  status.json                        состояние: версия, API, root, apk_patching, network
  roles/active-profile.json          роль, переданная приложением через configure
  records/<package>.json             что и когда смонтировано, с каким sha256
  logs/platform.log                  журнал, обрезается до 5000 строк
  cache/ inbox/ backup/              рабочие каталоги
```

## Команды

| Команда | Что делает | Коды возврата |
|---|---|---|
| `status` | перезаписывает и печатает `status.json` | 0 |
| `discover P` | путь к base.apk, `version_name`, `version_code`, размер, список split | 1 — не установлен |
| `configure B64` | сохраняет роль из base64-JSON в `roles/active-profile.json` | 2 — плохой payload |
| `role` | печатает сохранённую роль | 0 |
| `mount P APK VER` | монтирует APK поверх установленного, только если версия совпала | 3 — версия не та, 4 — монтирование не удалось |
| `umount P` | снимает монтирование, удаляет запись, останавливает приложение | 1 — не установлен |
| `verify P` | `mounted`, `record_sha256`, `current_sha256`, `matches` | 0 |
| `logs`, `clear-logs` | журнал | 0 |

Каждая изменяющая состояние команда пишет строку в журнал до и после действия.

## Что считается «патчем»

Разделение, которое заложено в каталог:

- `runtime` — перевод в рантайме через LSPosed и словарь. Ничего не меняет на диске,
  работает для серверной части и для текста, который рисует Compose/View.
- `actions[].type = "bind_mount"` — подмена содержимого APK. Нужна для того, что нельзя
  перехватить в рантайме: строки, которые читаются ресурсами до инициализации хука,
  и ресурсы, закешированные системой.

Payload для `bind_mount` — **не собранное приложение**, а изменённые файлы внутри APK
(в первую очередь `resources.arsc`). Приложение забирает установленный APK с устройства,
подменяет в нём указанные записи, пересобирает контейнер и отдаёт результат платформе.
Код приложения не пересобирается: dex не трогается.

## Ограничение, о котором надо знать

Любое изменение байтов APK ломает его подпись. Старый модуль `themestore_ru_module_v3`
именно так и работал: его `base.apk` не проходит `apksigner verify` — подписи v2/v3 срезаны,
файл монтируется поверх установленного. Значит схема опирается на то, что установленная
версия не перепроверяется системой на этом устройстве.

Поэтому:

- платформа обязана сверять `version_name` перед монтированием (сделано, код 3);
- откат обязателен и должен быть одной командой (сделано, `umount`);
- при обновлении приложения из магазина монтирование снимается само, запись устаревает,
  и перевод нужно применить заново.

## Чего платформа не делает

- не качает из сети;
- не хранит каталог и переводы;
- не собирает и не подписывает APK;
- не применяет непроверенный адаптер: `apply` по-прежнему отвечает `no adapter applied` (код 3).
